# Skill corpus trigger and context reform validation

## Outcome

The 40 publishable skills now use discriminating trigger descriptions, ASCII entrypoints, and
hard entrypoint limits. Purposeful context remains available through explicit orientation or
planning routes. Generated manifests and the skills index were rebuilt from final sources.

## Authority changes and autonomous review

- `docs/REPO_STYLE.md` now owns the three-class context model, the ASCII-entrypoint and
  functional-UTF-8-reference rule, and the 150 physical-line / 8,000-character limits.
- `docs/EXPERT_SKILL-BEST_PRACTICES.md` now treats a description as a discriminating trigger and
  routes conditional detail from a thin entrypoint.
- The shared `delegate-manager-to-subagents` skill owns generic delegated-execution process;
  local skills retain only domain return, proof, and failure contracts. Live consumer catalogs
  were routed to their durable owners.
- Three independent cold reads agreed that all 16 revised descriptions select both intended
  specialist cases and reject both routine adjacent cases. Two readers briefly observed
  `html-game-parallel-builder` while it was absent during concurrent replacement; both reread the
  restored description and agreed on both positive and negative cases. This was a transient
  observation, not dissent.
- Independent review found and fresh owners repaired the task-material receipt, routed
  screenshot human/history framing, and stay-busy/html-game human gates. Fresh re-reviews
  accepted those repairs. Policy, planner, identity/catalog, quality, and trigger reviews passed.

The workflow has no human approval gate. Fixed fixtures, deterministic tests, direct route
checks, and independent subagent re-review resolve each recorded decision.

## Trigger and context evidence

The 16 audit targets have the required `P2/N0` behavioral result: their two intended requests
select the skill and their two routine adjacent requests do not. `repo-rules-reader` additionally
selects for explicit orientation, a workflow-required receipt, or substantial work without a
valid same-session receipt; it does not select simply because a bounded request contains code or
review work. A valid receipt remains authoritative until the scope or relevant guidance changes.

repository/documentation authorities and repository evidence; it did not load database, UI,
runtime, or testing authorities. Planner fixture B, a PostgreSQL plus Solid UI plus runtime/deploy
plus tests request, loaded the same core set, every affected concern authority, and
`EXECUTION_RESOURCES`. Both traces passed selective-context review.

## Encoding and identity evidence

Every file named `SKILL.md`, including non-live copies discovered by the dedicated test, is ASCII.
`ideonomy-plain` is ASCII throughout. Manual ideonomy inspection confirmed that its tree is ASCII,
corrected one matrix directional relation, and replaced four picker-comment dashes.

The only UTF-8 exclusions are these exact, functionally rich rendering references:

- `skills/planning/ideonomy-rich/rendering/README.md`
- `skills/planning/ideonomy-rich/rendering/atlas.md`
- `skills/planning/ideonomy-rich/rendering/chart.md`
- `skills/planning/ideonomy-rich/rendering/cycle.md`
- `skills/planning/ideonomy-rich/rendering/dictionary.md`
- `skills/planning/ideonomy-rich/rendering/list.md`
- `skills/planning/ideonomy-rich/rendering/scale.md`
- `skills/planning/ideonomy-rich/rendering/tree.md`

Independent manual inspection retained Unicode there only for functional notation and rendered
examples, and removed style-only Unicode elsewhere. The exclusion registry has no wildcard and
does not exclude any `SKILL.md`.

Each exception has a distinct rendering purpose; replacing the listed glyphs with ASCII would
change the notation or destroy the monospace diagram, rather than merely change typography.

| Exact UTF-8 path | Functional Unicode retained | Rationale |
| --- | --- | --- |
| `skills/planning/ideonomy-rich/rendering/README.md` | connector, frame, density, arrow, and marker glyph vocabulary | This is the shared legend that assigns semantic meaning to the literal glyphs every rendering recipe uses. |
| `skills/planning/ideonomy-rich/rendering/atlas.md` | multi-panel box frames, density/marker cells, axes, and callout arrows | The worked atlas demonstrates how simultaneous maps occupy panels; ASCII substitutions would collapse the panel boundaries and encoded cell states. |
| `skills/planning/ideonomy-rich/rendering/chart.md` | grid intersections, heavy/light frame lines, markers, and pivot callout | The chart's rows, columns, empty cells, and highlighted pivot are the notation being taught, not ornamental characters. |
| `skills/planning/ideonomy-rich/rendering/cycle.md` | rounded boxes, directional arrows, loop marker, and vertical flow | The recipe's recurrence is visible only through the closed path and directional flow glyphs. |
| `skills/planning/ideonomy-rich/rendering/dictionary.md` | heavy frames, nested panels, bullets/markers, arrows, and status marks | The example uses frame weight and marks to distinguish complete entries, attributes, and verification state. |
| `skills/planning/ideonomy-rich/rendering/list.md` | rounded grouping frame and ranked/density markers | The list recipe teaches hierarchy, rank, and emphasis through the glyph roles specified in its example. |
| `skills/planning/ideonomy-rich/rendering/scale.md` | continuous axis, markers, density gradient, arrows, and pivot indicator | Position and density are the scale's data encoding, so an ASCII-only representation would not preserve the rendered example. |
| `skills/planning/ideonomy-rich/rendering/tree.md` | branch connectors, boxes, density markers, and directional hierarchy | The tree recipe uses literal branch geometry to show parent, sibling, and child relationships. |

## Generation and validation commands

The current merged indexing front door validates sidecars and generates every tracked projection:

```bash
source source_me.sh && python3 index_lib/build_all.py
source source_me.sh && python3 index_lib/build_all.py --check
```

The manifest generator included 40 skills and skipped the one deprecated `old-*` skill; it wrote
the Claude, Codex, Cursor, and OpenCode projections. The index generator included the same 40 and
wrote `docs/SKILLS_INDEX.md`.

showed that indexing commands were also misplaced under standalone `tools/` while importing the

projection behavior there, made `install_lib/` consume it, and removed the test bootstrap's
top-level tools import path. The documented command now passes unchanged:
