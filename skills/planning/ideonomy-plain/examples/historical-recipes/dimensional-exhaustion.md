# Recipe: dimensional exhaustion
<!-- uses: dimension-identification, substitution -->

Identify all dimensions of the idea. For each dimension, substitute every reasonable value. Enumerate the entire neighborhood. The exhaustive enumeration *is* the expansion.

## Steps

1. **Identify dimensions.** Use multiple dimension-prompts (default: 5–8). Don't stop at the obvious ones; surface the dimensions you'd usually leave implicit. (See `methods/operators/dimension-identification.md` plus the dimension-prompts catalog.)
2. **For each dimension, list possible values.** Bound the list at "reasonable" — you don't need to enumerate all integers if longevity is one of the dimensions. Pick 3–5 representative values per dimension.
3. **Substitute, one dimension at a time.** Hold all others constant; vary one. Record the variant. (See `methods/operators/substitution.md`.)
4. **Record the population.** You now have ~5 variants per dimension × N dimensions = a few dozen idea-variants. Some named, some unnamed.
5. **Read the asymmetries.** Which dimensions are most generative (substitutions yield real, useful variants)? Which dimensions are inert (substitutions yield only nonsense)? Inert dimensions are not load-bearing for this idea.

## Why it works

Most ideation explores one or two dimensions and stops. Dimensional exhaustion forces variation along *every* identified dimension. The breadth-first sweep surfaces variants that depth-first ideation would miss because depth-first locks in the first interesting dimension and never explores the others.

## When to use

When the user is producing variants but they all cluster in one region of idea-space. The recipe forces them into the unexplored corners.
