# Role guidance

Use the roles and ownership defined by the approved plan. Select the smallest role that completes the task.
Each closed assignment receives a fresh agent; live questions and answers may continue within its active
assignment.

## Roles

| Role | Responsibility |
| --- | --- |
| manager | Owns dispatch, decisions, dependencies, review routing, and acceptance. |
| implementer | Changes assigned files or behavior and returns evidence-rich handoff. |
| specialist | Resolves a narrow shared-interface or domain decision with evidence. |
| specification reviewer | Independently checks plan compliance before quality review. |
| quality reviewer | Independently evaluates quality after specification acceptance. |
| integration reviewer | Evaluates composition, architecture, and complete plan coverage. |

## Model selection

Inspect the live agent catalog before dispatch. Explicitly select a smaller, cheaper model than the manager by
default, choosing the smallest model capable of the assigned work. Record the capability reason in the brief
when a larger model is necessary or no cheaper suitable model is available. Avoid fixed model lists because the
live catalog is authoritative. Record the exact model identifier verified against the currently available
model catalog in each brief; a plausible model name is not evidence of availability.

If evidence shows the assigned model cannot complete the work, preserve the evidence in the handoff and assign
a fresh replacement agent with the appropriate capability. Do not rely on repeated underperforming retries.

## Handoffs

Every role reports the assigned outcome, examined or changed deliverables, exact commands and decisive output,
decision identifiers and application evidence, findings or concerns, skipped checks, and residual risks.
Reviewers also state review scope and cite each finding with file/line or command evidence.
